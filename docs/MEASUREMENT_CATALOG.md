# 측정값 분류와 유효성

숫자가 크다는 이유만으로 서로 직접 비교하면 안 된다. 이 문서는 각 결과가 무엇을 포함하는지와 현재 사용할 수 있는 결론을 분리한다.

## 최종 근거로 사용하는 결과

### 전체 영상 분석 격리 비교

- 입력: 고정된 720p·60fps 255프레임, 720p·29.97fps 631프레임
- CPU: 시험 당시 운영 Worker 이미지 `sha-d3753fc9...`의 격리 컨테이너
- GPU: OCI→RunPod 업로드, CUDA 처리, NVENC, 결과 다운로드
- 반복: 각 2회, 중앙값
- 결과: 기존 CPU 대비 48.01%, 79.05% 단축
- 제한: 운영 사이트·Grafana 결과가 아님

2026-09-07 운영 이미지는 `sha-6743f353...`로 바뀌었다. 두 이미지의 HPE 실행 내용과 ONNX 가중치는 같다고 확인했지만, 이 차이를 숨기지 않고 최신 이미지 사이트 재검증을 별도 단계로 남긴다.

세부 원본은 `evidence/cpu_gpu_video_analysis_final_evidence.json`에 있다.

### CPU 직접 스트리밍 비교

- 변경: 중간 `mp4v` 영상과 재인코딩 제거
- 결과: 60fps 24.92%, 29.97fps 11.26% 단축
- 정확성: 자세 예측 JSON 완전 일치

세부 원본은 `evidence/cpu_stream_final_evidence.json`에 있다.

## 단계별 기술 근거로 사용하는 결과

| 시험 | 측정 범위 | 결과 | 용도 |
|---|---|---|---|
| 임의 입력 ONNX | 모델 계산만 | 51.83배, 110.28배 | GPU 연산 가능성 |

| 약 36~38초 탐색 | 사이트 전체 | 자세 추론 약 5배 | 긴 영상 경향 참고 |

## 최종 결론에서 제외하거나 주의하는 결과

### 분석 이름만 CPU/GPU로 붙인 작업

공식 Worker 재배포 후 GPU 분기가 사라진 시점에는 `gpu_ab`라는 이름을 사용해도 실제로는 OCI CPU가 실행됐다. 라우팅 코드·환경변수·GPU 증거를 확인하지 않은 작업은 GPU 결과로 사용하지 않는다.

### 서로 다른 파이프라인 버전

과거 9단계 파이프라인과 현재 6단계 `video_analysis` 파이프라인의 단계 시간은 직접 비교하지 않는다.

### 실패한 피처 작업

stride 부족, 보행 이벤트 검출 실패, NaN 리포트로 종료된 작업은 성능 중앙값에서 제외하고 강건성 문제로 별도 기록한다.

### 긴 영상 탐색값

원본 길이가 기록마다 약 36초와 38초로 달라 최종 수치가 아니라 경향 증거로만 사용한다.

## 공정 비교 조건

- 동일 입력 SHA-256
- 동일 소스·모델 해시
- 동일 출력 FPS·프레임 수·해상도
- 같은 분석 범위
- 모델 적재 상태를 명시: cold 또는 warm
- 네트워크 포함 여부 명시
- 반복 실행과 중앙값 사용
- CPU/GPU 자세 결과 비교
- 실패 작업과 무효 작업을 숨기지 않음
- CPU/GPU 인코더가 다르면 출력 화질 동등성도 별도 검증
